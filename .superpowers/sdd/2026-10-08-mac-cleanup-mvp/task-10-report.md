## Delivered

- Added deterministic Markdown reporting sorted by batch id and target id. It names
  verified, suspended, skipped, pending, and failed targets from durable session
  state.
- Added a strictly validated, atomic `outcomes.json` session artifact. Direct apply
  and verify commands persist exact logical-removal records, `df` measurements,
  regenerated bytes/ids, issues, and suspension state without weakening or changing
  authoritative `state.json`.
- Extended `BatchOutcome` with per-target logical removal counts while preserving its
  existing positional field order.
- Reports keep estimated logical bytes, removed logical bytes, observed `df`
  free-space delta, and regenerated bytes/ids separate. Missing and already-absent
  removal measurements render as `unknown`; logical sums are explicitly not described
  as net recovered space.
- Issues are grouped under all four severities and required actions identify exact
  suspended/pending/failed targets, critical-stop handling, and administrative steps.
- Completed all six CLI commands:
  - `scan` creates/resumes a session, detects fixed modules/tools, performs fixture-safe
    two-pass discovery, and writes `inventory.json` plus a default policy when absent.
  - `plan` reads and strictly reconstructs inventory/policy, writes the immutable
    manifest, and prints deterministic batch/digest/estimate summaries.
  - `approve` reuses exact Task 7 digest validation.
  - `apply` reuses Task 8 dry-run/direct execution and records non-dry-run outcomes.
  - `verify` reuses Task 8 verification and Task 9 administrative result import.
  - `report` validates one coherent session snapshot, atomically regenerates
    `report.md`, and prints only its path.
- CLI results are concise deterministic JSON except `report`, whose contract is the
  report path. Exit codes are `0` success, `2` invalid input, `3` batch suspension,
  and `4` critical safety failure.
- Administrative fallback generation and reporting call Task 9's engine validator.
  Both surface the exact script path and validated SHA-256 and require executing that
  exact path, not a copy or replacement. They explicitly state that validation does
  not close the later manual validation-to-execution gap against a malicious same-UID
  actor. Divergent bound artifacts return code `4` without execution.
- Preserved the keyword-only trusted-home fixture seam and kept dry-run free of target,
  lifecycle, report, and outcome mutation. Tests inspect/remove only temporary fixtures.
- Deferred entrypoint imports until invocation and added an import-without-execution
  regression.

## Fix round 2

Status: DONE

### Review findings addressed

- Added a strict, read-only outcome-history preflight shared by apply and verify.
  Both commands now hold one reentrant `Session.operation_lock` from that preflight
  through dry-run/admin import or generation/direct execution and non-dry outcome
  recording. Missing accounting remains an in-memory empty history; dry-run does not
  create it. Malformed history returns code `2` before target or lifecycle mutation.

  outcome recording. Fixture regressions cover a forged writer ordered before apply
  and a writer blocked across the mutation-to-accounting boundary.

  absolute resolved canonical spelling. Trailing slashes, dot segments, duplicate
  separators, symlink aliases, relative paths, control characters, and unresolvable

  Reversed and duplicate otherwise-valid issues return code `2` without report
  mutation. Per-target removals, regenerated ids, operations, and inventory lists
